Status meanings

StatusMeaning
pendingThe run has started on the phone but no step has started yet in the imported evidence.
runningSteps have started but no run_finished event is in the imported evidence. Import again after the run ends; a stale import can also look like this.
passedEvery required step completed and all required evidence is present and consistent: the app received an acknowledgement carrying the same request ID AND the collector holds exactly one stored record for that ID with matching run and step IDs, under the test's preconditions (e.g. observed transport exactly 'wifi').
failedThe test ran with its preconditions satisfied and the evidence contradicts the expected behaviour, e.g. a request was not acknowledged, an ack carried a different ID, or the collector stored duplicates. For these connectivity/reliability checks a failure is a connectivity or reliability observation, never a security finding.
inconclusiveThe evidence cannot support passed or failed: preconditions were not met (transport not exactly 'wifi', traffic arrived via loopback), the user did not act in time, the run was cancelled, or the server evidence needed for confirmation is not available. A missing server record alone is never treated as proof of blocking.
execution_errorThe harness itself could not execute the test correctly: invalid configuration (endpoint/mode mismatch, cleartext not permitted for the host), evidence could not be written, the app process ended mid-run, or app evidence is internally inconsistent (duplicate request IDs).

Limitations

  • Connectivity and reliability observations only; no security property is tested or claimed.
  • Observed transport is Android's report for the default network; it is not independently verified.
  • USB-mode traffic travels over adb reverse (USB) and says nothing about Wi-Fi.
  • Phone and Mac clocks are not synchronised; durations use each device's own monotonic clock and are never computed across devices.
  • Wait-step outcomes (restart observed, Wi-Fi loss/return observed) are app-side observations.
  • Single observations of elapsed time are not benchmarks.
  • ANDROID_WIFI_TELEMETRY (RSSI, frequency, link speed) is platform-reported, coarse and possibly cached; it is not CSI. Repeated values are not counted as fresh samples.
